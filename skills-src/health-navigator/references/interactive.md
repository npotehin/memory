# Личный интерактивный отчёт

Чат по умолчанию; для повторных измерений/нескольких документов или по запросу
сделай мобильный offline HTML. Browser JS обеспечивает взаимодействия, Python
готовит данные, сложные графики — локальный Plotly/data-analysis. Не создавай
отдельный frontend/backend/MCP ради отчёта. Используй доступный Apps путь только
при фактической поддержке персонального хранения, не обещай его из инструкции.

Views по данным, а не обязательно все семь:

- **Обзор:** выбранный профиль, вопрос/последние события, охват истории,
  pending/неизвестные сведения, ближайшие подтверждённые задачи.
- **История:** хронология с фильтром события/периода, источником и статусом факта,
  предположения/установленное/прошлое различаются текстом, не одним цветом.
- **Показатели:** выбор метрики/периода/метода, реальные точки, единицы,
  индивидуальные референсы, таблица и переход к исходной странице.
- **Симптомы:** дневник и сводка, изменения оценок/шкал объяснены; совпадения
  во времени не оформлены как причинность.
- **Назначения:** prescribed/actual, источник, уточнения и план/факт. Отметка
  в snapshot не подтверждает доставленное напоминание или автоматически приём.
- **К врачу:** компактная выжимка, список вопросов и выбранных приложений,
  реальные кнопки export PDF/JSON/CSV или ясная команда в чат для подготовки.
- **Источники:** thesis → recommendation/PMID → применимость/uncertainty →
  покрытие чтения. Ссылка на поиск не заменяет источник конкретного тезиса.

Отдельные профили; все таблицы/графики/счётчики/экспорт применяют тот же выбор
профиля/периода. Scope не переключается кнопкой на чужого пользователя. Child
рост/женский дневник появляются только по нужным данным; не показывай вымышленные
результаты/проценты здоровья для пустой истории.

Snapshot явно содержит revision/as-of и локальность. Правки экспортируются
кандидатом и возвращаются Hermes для review/CAS; localStorage не общий backend
и не синхронизация. По умолчанию не сохраняй медицинские данные в localStorage
на общем устройстве. Не публикуй отчёт на public hosting. Локальные/inline assets,
без внешних analytics/fonts/CDN/API с журналом. Для внешней source link используй
обычную проверенную ссылку, не медицинские данные в query string.

Любой текст документа/имя/label экранируется; embedding JSON защищается от
закрытия script tag. Скрипт из выписки не выполняется. Реальные оригиналы не
встраиваются в общий dashboard без нужды/согласованного контекста отправки.

## Headless QA

Проверь на desktop/mobile: разные профили, period/metric filters и точность
счётчиков; разные units/methods/references; partial/missing/pending/censored;
timezone/date-only, amendments и повтор; пустой профиль/одна точка/длинные labels.
Сравни числовые series/экспорт с первичным журналом, не только наличие canvas.
Проверь keyboard/focus, контраст, читаемые подписанные оси/легенду, console errors,
реальные внешние ссылки и каждую основную кнопку. PDF — через documents render QA.

Native browser-use/Chromium даёт настоящие скриншоты обзора/графиков и визуальную
проверку при доступном sandbox. Доставь через native sender. Без браузера/канала
проверки явно укажи непроверенное; создание HTML само по себе не visual QA.
Все demo records явно synthetic; скриншот демо не подтверждает пользовательский E2E.
