# Выразительная презентация: проверенный подход

Подход проверен на рассказе о производстве Blade Runner 2049 и одобрен пользователем. Переиспользуй логику, композиции и качество движения; тема фильма, оранжевая палитра и число слайдов не становятся обязательными для остальных презентаций.

## Из замысла в сцену

Открытие показывает впечатляющий результат и задаёт вопрос «как это стало возможным?». Дальше представь участников, цель и ограничения. Показывай решения через реальные материалы: процесс, артефакты, масштаб, механизмы и изменение состояния. Свяжи их в кульминации. В финале верни начальный образ с новым пониманием.

В деловой презентации тот же приём может начинаться с результата продукта, объяснять решения и завершаться предложением. В учебной — начинаться с явления, показывать механизм и возвращаться к объяснённому явлению. Выбирай подходящую структуру из `storytelling.md`.

## Композиции, которые можно сочетать

| Задача сцены | Композиция | Движение с назначением |
|---|---|---|
| Обещание и финальный ответ | Полноэкранное фото/кадр; крупная короткая типографика; локальный градиент под текстом | Конечный мягкий camera push на изображении, неподвижный текст |
| Сформулировать проблему | Просторная типографическая сцена; один вопрос или напряжение между двумя состояниями | Раскрытие ключевой мысли по клику |
| Показать участников/артефакт | Большое фото занимает примерно половину сцены; краткие роли/контекст рядом | Маска открывает изображение, подписи появляются спокойно |
| Объяснить развитие во времени | Связная линия событий; при необходимости параллельные дорожки | Линия достраивается; события раскрываются в нужном порядке |
| Передать масштаб | Крупное число + реальный объект + единица измерения/сопоставление | Изображение или шкала раскрываются; число остаётся читаемым |
| Объяснить механизм | Реальное свидетельство рядом с подписанной технической схемой | Движение показывает работу механизма: направление света, поток, сборку |
| Показать материальность | Галерея с разными пропорциями изображений, короткие предметные подписи | Умеренно разнесённое по времени раскрытие фотографий |
| Сопоставить состояния | Два сопоставимых изображения/данных либо большая управляемая область сравнения | Wipe/crossfade/ползунок, если исходники действительно позволяют сравнение |
| Разобрать эффект | Процесс/геометрия/слои и итог; подписи различают стадии | Управляемая сборка; один краткий характерный эффект на изображении |
| Соединить доказательства | Один сильный пример и краткая смысловая последовательность | Составляющие раскрываются и сходятся в общей мысли |

Переход между сценами меняет визуальный режим: плотное/просторное, тёмное/светлое, предметное/типографическое, статичное/объясняющее движение. Один стиль связывает их, но не требует одного макета. Повтор композиции открытия в финале может быть осмысленным возвращением.

## Визуальный ориентир

Для сцены 1280×720 удачная исходная сетка: поля около 64 px; заголовки примерно 50–75 px, обычный текст 23–30 px; крупные числа могут занимать существенную долю сцены. Заголовок не должен занимать место доказательства. Второстепенные кредиты допустимо сделать меньше, основной вывод — нет. Эти значения адаптируются после реального рендера.

В проверенном примере использовались тёплый почти чёрный фон, светлый текст, янтарный акцент и светлые предметные сцены. Для другой темы выбери подходящую палитру; держи основной текст контрастным, число акцентов небольшим, а фактуру — в настоящих изображениях. Не накладывай одинаковые декоративные эффекты на каждый слайд.

## Динамика без дёрганости

Заголовки держат позицию. Более заметное движение происходит в изображениях, схемах и переходах состояния. Fade подходит подписи; процессу нужен эффект, который показывает процесс. Краткое стилистическое расслоение уместно для цифрового сбоя, но не для всех заголовков. Длинное объяснение должно управляться зрителем; разреши повтор сцены и отключение движения.

Используй навигацию и управление анимациями OpenSlide; сценовые эффекты согласуй с его жизненным циклом. Проверяй, что их последняя поза совпадает с CSS/DOM: по завершении анимации объект не должен возвращаться скачком. Переход к следующему фрагменту оставляет вход текущей сцены в покое. Подробности реализации и проверки — в `design-motion.md`.

## Что передавать для оценки

Самостоятельный HTML с локальными ресурсами, статичный PDF при необходимости, контактный лист и короткую реальную запись сложных эффектов. Дай управление и реальные ссылки на источники. В печать попадает полный смысл каждого слайда. Проверяй клавиатуру также после клика по кнопке: фокус на toolbar не должен выключать стрелки/Home/End.

Смотри не только на отсутствие переполнения: действительно ли виден механизм, чувствуется ли масштаб, понятен ли переход мысли и отличается ли композиция от соседней? Сохраняй доказательность: нельзя заменять производственный материал красивой реконструкцией или выдавать разные кадры за точную пару до/после.
