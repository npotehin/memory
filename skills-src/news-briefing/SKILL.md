# Персональные дайджесты

Для работы с файлами, HTML и sandbox читай общую инструкцию
[references/runtime-and-delivery.md](references/runtime-and-delivery.md).

Дай человеку понятную картину выбранного периода: что произошло, что изменилось,
почему это относится к его интересам и где прочитать первоисточник. Используй
нативные web/search/extract, recall, доступные источники и доставку файлов.
Скилл задаёт редакционный процесс; сборщик лент и планировщик остаются штатными.

## Выбор ветки и этапа

Выбери ветки по требуемому результату. Прочитай указанные инструкции перед
соответствующим этапом; осмотр вложений и уточнения могут предшествовать ему.
В составной задаче загружай ветки по мере перехода к этапам, а не весь пакет.

| Задача | Инструкция | Когда читать |
|---|---|---|
| Разовый дайджест и проверка событий | [references/sources-and-evidence.md](references/sources-and-evidence.md) | Перед поиском, отбором и объединением публикаций |
| Регулярные редакционные выпуски | [references/recurring-briefings.md](references/recurring-briefings.md) | Перед формированием самостоятельного задания cron |
| Интерактивный дайджест | [references/interactive-briefing.md](references/interactive-briefing.md) | Перед проектированием страницы |

## Задание и персонализация

Возьми из запроса и доступного контекста темы, компании/людей, регион, язык,
источники, исключения, глубину и период. Не требуй онбординга для разовой сводки.
Если темы не заданы, собери разнообразную общую подборку и коротко обозначь охват.
Явно заданные источники сохраняй; дополнительный web используй для проверки,
помечая новости вне выбранной коллекции. Личные интересы сохраняй штатной memory
при её доступности; содержимое выпусков туда не записывай. Не обещай память между
сессиями, если доступного постоянного состояния нет.

Разреши относительный период по текущей дате и часовому поясу пользователя.
Зафиксируй начало, конец и время проверки. «Сегодня» — местный календарный день,
«последние сутки» — скользящие 24 часа. Для неуточнённого «за неделю» используй
последние семь дней и покажи границы. Время проверки может предшествовать концу
запрошенного периода: будущую часть не объявляй покрытой.

## Поиск, доказательства и отбор

Сначала найди кандидатов, затем проверь существенные утверждения в самих материалах.
Следуй нативной маршрутизации многоисточникового research/background: передавай
полный бриф в существующий исследовательский инструмент, если он доступен.
Не расширяй toolsets concierge и не повторяй pending/busy-задачу ради результата.

Для каждой новости различай событие, публикацию, обновление страницы и время
получения. Новая дата страницы не делает старое событие новым. У старой истории
включай только конкретное существенное изменение за период; старый контекст помечай.
Неизвестную дату не восстанавливай по URL, позиции в поиске или относительной метке.
Подробности: [references/sources-and-evidence.md](references/sources-and-evidence.md).

Объединяй перепечатки одного события в один пункт. Проверяй совпадение участников,
предмета и фактического изменения; разные релизы одной компании не обязательно
дубли. Отдельное подтверждение, опровержение или новый этап могут стать обновлением
истории. Несколько пересказов одного пресс-релиза не являются независимыми источниками.

Отбирай по соответствию интересам, значимости изменения и качеству доказательств.
Число пунктов адаптируй к запросу: не заполняй квоту слабыми или старыми новостями.
Разделяй «заявлено/анонсировано», «выпущено/доступно», «независимо подтверждено»,
«слух/мнение» и «опровергнуто». Заявление компании подтверждает само заявление,
но не обещанные результаты. Объяснение последствий маркируй как вывод, когда оно
не следует непосредственно из источника; фактическую сводку не подменяй советом.

## Результат и продолжение

Начни с наиболее важных изменений. Каждый пункт содержит конкретное событие,
краткое объяснение значимости и прямую ссылку; добавь дату там, где она проясняет
хронологию. Для спорного сообщения укажи статус и основание, сохрани противоречия.
Назови существенные пропуски покрытия: недоступные источники, обрезанный текст,
проверка только заголовков. Если новостей не найдено, так и сообщи в рамках
проверенного охвата; отказ источника не доказывает отсутствие событий.

«Подробнее о втором» продолжает выбранную историю; «ещё» исключает уже показанные
события. Для крупных подборок или запроса страницы создай интерактивный HTML:
[references/interactive-briefing.md](references/interactive-briefing.md).
При доступном sandbox используй штатный browser-use для проверки страницы и
существенных спорных ссылок; полученные скриншоты отправляй через send_file.
Для обычной короткой сводки HTML не обязателен.

## Повторные выпуски и источники

По поручению на регулярную доставку используй cron с `kind="agent"` и
`skills=["news-briefing"]`. Промпт должен быть самостоятельным: будущий запуск
не наследует эту беседу. Формирование задания, сравнение выпусков и проверка
расписания: [references/recurring-briefings.md](references/recurring-briefings.md).
Разовая сводка сама по себе не создаёт подписку.

Если доступны подключённые персональные news tools, RSS/Atom или MCP, используй
их в пределах подтверждённой возможности и личности пользователя. Иначе работай
через web. Для больших документов/транскриптов переиспользуй source-research;
ветку получения video-audio — для доступных субтитров, а не обещания просмотра
видео по заголовку. Запрос «уведомляй при изменении этой страницы/новом ID»
передавай change-monitoring; редакционный выпуск остаётся news-briefing.
Выбор источника и будущая интеграция krche:
[references/source-integrations.md](references/source-integrations.md).
