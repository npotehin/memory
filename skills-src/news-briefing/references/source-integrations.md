# Источники и интеграции

## Порядок выбора

1. Явно выбранные пользователем и доступные персональные источники/tools.
2. Нативные web search/extract для поиска, полного текста и независимой проверки.
3. Прямые публичные RSS/Atom/JSON feeds при доступном пользовательском sandbox.
4. Подтверждённый MCP, если он даёт нужный доступ, которого предыдущие пути не дают.

Не устанавливай отдельный RSS-reader, embeddings, базу статей или scheduler ради
обычной подборки. Для большого корпуса используй source-research. Закрытый канал,
paywall или отсутствие доступа к истории нельзя заменить обещанием полного покрытия.
Telegram-публикации читай только через реально доступную ссылку/подключение; не
обещай доступ ко всем сообщениям канала и не создавай пользовательский аккаунт.

## Публичные ленты

Feed — способ обнаружить материалы, а не доказательство каждого утверждения.
Сначала получи записи, затем открывай только отобранные исходные статьи. Feed может
содержать только последние записи; отсутствие в нём не доказывает отсутствие
публикации за весь интервал. Сохраняй GUID/Atom ID, исходные ссылки и даты как данные,
не превращай дату feed update в дату события.

При первом нужном вызове проверь наличие парсера в постоянной проектной среде
sandbox. Для обычного RSS/Atom достаточно Python stdlib HTTP/XML; XML нельзя
разбирать регулярными выражениями. Используй нативные ограничения сетевого доступа,
таймаут, ограниченный размер ответа и проверку конечного адреса после redirects;
не отключай их ради ленты. Если форматы сложнее, выбери проверенную закреплённую
версию feedparser в проектном venv, установи её только там и проверь один выбранный
feed. Переиспользуй рабочую установку; не скачивай весь архив издателя.

Официальная документация: [Python XML](https://docs.python.org/3/library/xml.etree.elementtree.html),
[feedparser](https://feedparser.readthedocs.io/en/latest/).

## MCP

Отдельный feed MCP не требуется: stdlib XML/проверенный feedparser закрывают
публичные ленты в существующем sandbox. feed-mcp (37 звёзд на 2026-10-09) исключён
из default установки/вызовов. Для нового стороннего MCP требуется конкретный repo
>1000, лицензия, pin, источник, изоляция состояния и реальный read-only smoke.
Порог относится только к MCP, не библиотеке feedparser. Не снимай no_mcp-гейты
и не создавай второй scheduler/backend для RSS. При ошибке продолжай native web.

## krche — будущая интеграция

Сейчас пакет не подключает krche. Не вызывай придуманные endpoints или будущие
тулы и не запрашивай служебные ключи у пользователя. После реализации штатной
интеграции проверь фактически выданные схемы news_feed/news_sources/news_interests
или их актуальные аналоги, доступность в интерактивном и cron-контекстах и привязку
к тому же человеку. Shared/test feed не объявляй личной коллекцией.

Ленту используй для отбора, полный материал — для проверки, исходный URL — для
ссылки. Сохраняй krche entry/story ID для продолжения разговора и сравнения выпусков.
Пересказ внутри krche не является независимым источником или подтверждением.
При обрезанной статье/ошибке ответа обозначай ограничение. Истории и группы дублей
krche — подсказки для редакционного объединения, их конкретные утверждения проверь.

Чтение ленты не разрешает добавление/удаление подписок, изменение интересов,
mark-as-read или сброс. Такие действия выполняй по соответствующему поручению
через нативную интеграцию и её правила подтверждения. Для обычного дайджеста они
не нужны. Скилл и формат результата остаются теми же при смене поставщика данных.
