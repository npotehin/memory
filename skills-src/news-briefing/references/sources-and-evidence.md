# Источники, даты и события

## Карточка при исследовании

Для отобранного кандидата сохрани: заголовок события, участников, тему/регион,
что конкретно изменилось, дату события (или unknown), даты публикации/обновления,
часовой пояс дат при наличии, checked_at, прямые URL и источник каждого существенного
утверждения. Отдельно — статус сообщения и ограничения проверки. Эти поля нужны
для отбора и сравнения; не перегружай ими каждую короткую реплику.

При ссылках из ленты сохрани source_id/item_id и исходный URL. Извлечение полного
текста не означает, что он новее ленты. Заголовок/описание могут подтверждать только
видимые в них сведения; недоступную статью не пересказывай как прочитанную.

## Свежесть

- Дата в RSS/Atom — дата записи, а не автоматически дата описанного события.
- «Обновлено сегодня» у справки о прошлогоднем запуске не попадает в сводку запусков
  за сегодня, если содержательного нового факта нет.
- Если событие вчера, а публикация сегодня, для дайджеста событий за сегодня это
  старый контекст. Для явно заказанного дайджеста публикаций за сегодня оно допустимо
  с указанием даты события. По умолчанию отбирай изменения, произошедшие за период;
  поздно раскрытый факт обозначай «стало известно», сохраняя историческую дату.
- Объявленная будущая дата — план, не состоявшееся событие. Отмена или перенос
  анонса может быть свежим событием сам по себе.
- Не включай публикацию с неизвестной датой как доказанно свежую. При важности
  покажи её отдельным контекстом с неизвестной датой, без утверждения о новизне.

Для развивающихся событий проверь последние доступные обновления на checked_at.
Сохрани исправления/опровержения, даже если они меняют прежний вывод.

## Кластеры событий

Сопоставляй субъект + действие/изменение + объект/версию + период. Канонический URL,
ID материала, одинаковый заголовок и текст — подсказки, а не окончательное решение.
Не удаляй значимые параметры URL: ID видео, статьи и записи важны для идентичности.
Убирай только известные tracking-параметры. Разные URL могут вести на перепечатку;
один URL может позже получить исправление.

Выбери наиболее полный первоисточник и при необходимости независимую проверку.
Заявление пресс-службы и пять публикаций, ссылающихся на него, образуют одно семейство
доказательств. Не усредняй несовместимые числа: покажи, кто их сообщил, на какую
дату и с каким определением метрики. Предпочитай исправленную версию, сохраняя
ссылку на исправление и объяснение, если прежняя версия уже вошла в выпуск.

## Специальные подборки

**Компания/продукт:** release notes, официальное объявление, фактическая доступность
и независимый опыт могут описывать разные стадии. «Обещают функцию» не равно
«функция доступна всем». Сравнение ограничений опирается на проверенные документы.

**Исследования:** различай препринт, рецензируемую публикацию и пресс-пересказ;
указывай существенные ограничения эксперимента. Не делай медицинских/финансовых
рекомендаций из новости без отдельного запроса и соответствующей проверки.

**Видео/подкасты:** используй реальный ID, название, дату и доступный транскрипт.
Из описания выпуска нельзя вывести его содержание. Привязывай выводы к таймкодам,
если их удалось получить; иначе обозначай отсутствие транскрипта.

**GitHub:** различай Trending, новые releases и активность за период.
Общее число stars не является приростом за неделю; текущий список Trending —
не исторический рейтинг. Репозитории объединяй с описываемыми релизами, если
это один инфоповод; не заводи отдельный skill на каждый такой источник.
