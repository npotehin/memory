# Источники и MCP: минимальный рабочий путь

Наличие этих инструкций не означает подключение сервера. Сначала проверь доступные
native tools. Поиск/извлечение делай штатными web/research; прямые HTTP-запросы —
через существующий Python execution в пользовательском sandbox, если нужен
структурированный результат. Не расширяй главный concierge до `web`/`safe`.

## Допуск источника перед подключением

Строгое правило пользователя: сторонний MCP допускается только
при подтверждённых >1000 звёзд у конкретного проекта. Официальные API разрешены
без GitHub-счётчика: прямые NCBI/Europe PMC допустимы. Это исключение не относится
к сторонним MCP-обёрткам официальных источников. MCP-кандидаты ниже исключены.

## Справка API без платного ключа после проверки допуска

**PubMed / NCBI E-utilities**:
[правила](https://www.ncbi.nlm.nih.gov/books/NBK25497/),
[quick start](https://www.ncbi.nlm.nih.gov/books/NBK25500/).

- `https://eutils.ncbi.nlm.nih.gov/entrez/eutils/esearch.fcgi`:
  `db=pubmed`, `term=<запрос>`, `retmode=json`, нужные `retmax/sort`. Проверь
  `querytranslation` и ошибки, не только `idlist`.
- `.../efetch.fcgi`: `db=pubmed`, `id=<PMID через запятую>`, `retmode=xml`.
  Получай выбранные записи одним batch; обрабатывай отсутствующие поля и
  `CommentsCorrections`. Настоящий тип обзора может быть просто `Review`.
- Передавай имя приложения `tool` и реальный контакт разработчика `email`,
  когда он настроен. Не придумывай контакт и не используй личный адрес пациента.
- Без ключа NCBI ограничивает совокупность запросов одним IP тремя в секунду;
  отдельный limiter в каждом sandbox не обеспечивает общую квоту. API key
  опционален, не является платной подпиской. Уважай `429/Retry-After`, разумный
  backoff, batch и доступный cache. Не запускай массовый обход базы.
- При общем egress и отсутствии координации используй доступный native web,
  Europe PMC или сообщи об ограничении. Не утверждай, что последовательность
  запросов одного пользователя решает production rate limiting всей системы.

**Europe PMC**:
[REST reference](https://europepmc.org/RestfulWebService).

- `https://www.ebi.ac.uk/europepmc/webservices/rest/search`:
  `query=EXT_ID:<PMID> AND SRC:MED`, `resultType=core`, `format=json` для
  конкретной статьи; тематический поиск имеет собственный синтаксис.
- В `core` есть abstract, идентификаторы, типы, MeSH, ссылки и сведения о доступе.
  Source `MED`/`PMC`/`PPR` различай; препринты не считать опубликованными испытаниями.
- `.../<PMCID>/fullTextXML` отдаёт доступное open-access подмножество.
  Проверь `isOpenAccess`, лицензию самой статьи и ответ сервера. Не каждый PMID
  имеет PMCID, а PMCID сам по себе не разрешает перепубликовать весь текст.
- Доступ проверен без ключа, но это не обещание SLA/неограниченной пропускной
  способности. Нулевая выдача/сбой одного зеркала не доказывает отсутствие работы.

**wger public REST**:
[документация](https://wger.readthedocs.io/en/latest/api/api.html),
`https://wger.de/api/v2/` — discovery, `exerciseinfo/` — описания упражнений.
Публичные упражнения/оборудование доступны без учётной записи. Фильтруй/пагинируй,
проверяй фактическую схему и нужный перевод. Язык записей не гарантирован;
перевод на русский не выдавай за оригинальную демонстрацию. License/author
проверяй у текста, изображения и видео отдельно. Пользовательские журналы и
программы требуют персональной авторизации.

**Дополнительное чтение по вопросу**:
[WHO](https://www.who.int/publications/i/item/9789240015128),
[ACSM](https://acsm.org/resistance-training-guidelines-update-2026/),
[NHS](https://www.nhs.uk/live-well/exercise/),
[Cochrane abstracts/сводки](https://help.cochrane.org/kb/article/27-how-can-i-access-cochrane-evidence/),
[Минздрав РФ](https://cr.minzdrav.gov.ru/clin-rec).
У Cochrane доступны бесплатные abstract/понятные сводки; полный обзор может
требовать подписки. У Минздрава проверяй конкретный документ и статус, не
подставляй выдуманный API. Доступность сайта не равна разрешению копировать контент.

## MCP: проверка допуска >1000 звёзд

После аудита 2026-10-09 ни один из рассмотренных MCP не допущен к использованию
по правилу пользователя. Не устанавливай и не вызывай их, включая hosted endpoint.
Предыдущие protocol smoke — история исследования, не разрешённое подключение.

| Репозиторий | Звёзды | Допуск |
|---|---:|---|
| [cyanheads/pubmed-mcp-server](https://github.com/cyanheads/pubmed-mcp-server) | 156 | Нет |
| [andybrandt/mcp-simple-pubmed](https://github.com/andybrandt/mcp-simple-pubmed) | 172 | Нет |
| [CellCS/pubmed-mcp](https://github.com/CellCS/pubmed-mcp) | 0 | Нет |
| [wger-project/mcp-server](https://github.com/wger-project/mcp-server) | 5 | Нет |
| [genomoncology/biomcp](https://github.com/genomoncology/biomcp) | 650 | Нет |

[wger-project/wger](https://github.com/wger-project/wger) — 7076; прямой
API платформы доступен без порога MCP. Это не разрешает её MCP с пятью
звёздами и не требует разворачивать полную платформу локально.

Новый сторонний MCP runtime используй только после проверки конкретного
репозитория: строго >1000, дата/ссылка/точный счётчик, лицензия, pinned версия и
read-only smoke. Недоступный счётчик — не подтверждённый допуск. Популярность
клиента, SDK или базовой платформы не переносится на отдельный MCP-сервер.

Официальные NCBI/Europe PMC API разрешены пользователем независимо от наличия
GitHub-счётчика. Используй прямые endpoint выше, сохраняя общий NCBI rate limit,
batch/cache и критерии доказательности. Для HTTP достаточно stdlib Python или
имеющегося проверенного клиента; низкозвёздочный PubMed MCP не требуется.
WHO/NHS/ACSM/КР — источники публикаций, которые читаются через native web.

Не меняй общий конфиг MCP, не добавляй контейнер или scheduler ради этого навыка.
Если новый MCP не проходит фильтр, продолжай через штатные инструменты и допустимый
прямой API; не ищи обход через малопопулярную обёртку или публичный relay.

Собственный stdlib helper: [references/official-api.md](official-api.md).
Порог касается только MCP, не Natasha/SDK/транзитивных библиотек.
