# Страница, помогающая заниматься

Создавай полноценный HTML для программы/прогресса при sandbox; быстрый вопрос
оставляй чатом. Mobile first, русские подписи, понятные единицы, хорошая читаемость,
клавиатурный доступ и спокойная анимация с reduced-motion. Не превращай обычный
фитнес-дневник в экран медицинской диагностики.

Основные views:

1. **Сегодня:** конкретное занятие, длительность, объяснения движений, облегчённая
   версия и понятный способ записать факт. Для отдыха — отдых, не пустая ошибка.
2. **Неделя:** календарь план/факт, перенос будущего дня, повтор этапа и переключение
   доступного времени. Изменения реально обновляют будущую сетку и объём.
3. **Запись:** фактические подходы/время/дистанция, усилие с объяснённой шкалой,
   заметка и статус. Запланированные цифры не подставлять как подтверждённый факт.
4. **Прогресс:** выбранный период/упражнение, согласованные фильтры, графики факта,
   таблица первичных записей и покрытие истории. Пустой журнал предлагает начать
   запись; нет вымышленных демонстрационных результатов в личном отчёте.
5. **Почему так:** раскрываемые карточки источников: тезис, кого изучали, уверенность,
   ограничения, что меняет выбор; кликабельные PubMed/официальные ссылки.

Offline HTML — snapshot. Возможны локальные правки и JSON/CSV-экспорт, но их нужно
вернуть в Hermes для сверки и обновления canonical journal. Если используется
localStorage, объясни локальность и потерю при очистке; оно не синхронизирует другие
устройства. Не обещай уведомления/запись в часы без рабочего backend. Кнопки без
канала действия замени понятным экспортом или инструкцией в чат.

Python генерирует данные/HTML; браузерный JS даёт взаимодействия. Простые графики
можно строить SVG, более сложные — offline Plotly по `data-analysis`. Скрипты/ассеты
подключай локально или inline; страница не должна слать личный журнал во внешнюю
аналитику/CDN. Не публикуй страницу с персональными данными в общий хостинг.

Перед доставкой через native browser-use/Chromium headless проверь:

- сегодня/отдых, пустую и неполную историю, длинные названия на desktop/mobile;
- фильтр периода, переключение упражнения, запись partial, перенос/повтор недели;
- невозможные/отрицательные значения и будущие даты; экспорт/повторный импорт;
- агрегаты по исходным записям, пропуски как unknown и отсутствие двойного импорта;
- все основные кнопки, реальные ссылки, доступность и отсутствие console errors.

Доставь рабочий артефакт и настоящие скриншоты обзора/прогресса. Если браузер или
канал проверки недоступен, сообщи что именно не проверено; не называй headless QA
завершённым по одному успешному созданию HTML.
