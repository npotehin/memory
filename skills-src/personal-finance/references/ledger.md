# Выписки, нормализация и сверка

## Импорт

Сохрани оригинал неизменным, его hash и источник каждой строки: файл, лист/строка
или страница PDF. Определи владельца и охват счетов: один человек или домохозяйство.
Совместные/личные расходы различаются меткой участника, не вторым импортом той же
операции. Один счёт может встречаться в банковской и ручной выгрузке.

Осмотри заголовки, разделитель, кодировку (UTF-8/Windows-1251), десятичную запятую,
обычные/неразрывные пробелы, валюты, даты и знаки. Сумма операции в валюте покупки
и фактически списанная сумма в валюте счёта — разные поля. Формат по названию
банка не угадывай. PDF-таблица может переносить описание между страницами;
OCR/нечитаемые суммы требуют проверки, не автоматического включения в итог.

Нормализованный журнал содержит стабильный `id`, source locator, `account_id`,
владельца, дату операции и проводки, `status` (posted/pending/reversed),
`amount_minor` со знаком в валюте счёта, `currency`, exponent, исходное описание,
получателя, исходную/подтверждённую категорию, `kind`, связи transfer/refund,
статус ручной проверки. Доступный остаток с холдами не равен бухгалтерскому.
Для RUB minor units — копейки; не обобщай два знака на все валюты.

Если нет банковского transaction ID, создай fingerprint из счёта, дат, суммы,
валюты, описания и сохранённого количества одинаковых строк. Перекрывающиеся
выгрузки сверяй по периоду и кратности; две реальные одинаковые покупки нельзя
удалять как один дубль. Переход pending → posted обновляет связь, не добавляет
второй расход. Сомнительные совпадения показывай для подтверждения.

## Экономический смысл

| Операция | Учёт |
|---|---|
| СБП между своими счетами | Две связанные проводки, исключены из доходов/расходов домохозяйства; комиссия — расход |
| СБП другому человеку | Перевод сам по себе не определяет назначение; возможны покупка, подарок, общий счёт, заём |
| Снятие наличных | Перевод в кошелёк, если учитываются наличные; без его журнала расход наличных неизвестен |
| Покупка кредитной картой | Расход в момент подтверждённой покупки и увеличение долга |
| Погашение кредитной карты | Перемещение денег/уменьшение долга, не повторная покупка; проценты/комиссии отдельно |
| Получение кредита/возврат выданного займа | Финансирование/возврат основного долга, не заработанный доход |
| Платёж по кредиту | В cash flow весь платёж; в расходах проценты/комиссии, основной долг уменьшает обязательство |
| Возврат покупки | Связь с исходным расходом и его категорией; фактическое поступление на дату возврата |
| Вклад/брокерский счёт | Перевод собственных средств не доход и не потребление; проценты/дивиденды отдельны |
| Кешбэк | Явная последовательная политика: отдельный доход или снижение расходов; не учитывать обоими способами |

Успешный transfer match требует данных об обеих сторонах; совпадение суммы
не является доказательством. Межвалютный перевод может иметь разные суммы и
комиссию. Если другая сторона за пределами выбранного фильтра, не превращай
перевод автоматически в потребление. Даты обеих сторон могут лежать в разных
месяцах: покажи деньги в пути при сверке.

Возврат прошлого месяца не переписывает его cash flow. Для анализа стоимости
покупки можно дополнительно собрать purchase cohort; покажи метод отдельно.
Непривязанный возврат остаётся видимым и не маскируется как зарплата.

## Валюты и сверка

Храни фактические суммы отдельно по валютам. Для отчёта в RUB предпочитай
банковскую сумму проводки; иначе указывай метод и датированный курс.
ЦБ публикует `Value` за `Nominal`: RUB за единицу = Value / Nominal.
Используй фактическую дату действия ответа, включая выходные, не будущий курс.
Сделки — по исторической дате; snapshot активов — по дате оценки. Валютную
переоценку отделяй от новых накоплений. Официальный курс не курс обмена в банке.

По каждому полностью покрытому счёту/валюте проверь:
`opening_book_balance + sum(posted signed movements) = closing_book_balance`.
Для долга заранее определи знак: обязательство положительное, актив отрицателен
либо отдельные поля. Покажи ожидаемый/рассчитанный остаток и разницу. При неполном
периоде, отсутствии opening balance или несовместимом closing balance статус
«не сверено», а не «0 ошибок». Несверенные счета не доказывают размер подушки.

Агрегаты расходов, денежного потока и изменения капитала считаются разными
проекциями одного журнала. Для импорта проверяй row count, rejected rows,
количество повторов, валюты и контрольные суммы. Храни категории/решения отдельно
от оригинала, с журналом правок. Не передавай личные операции в публичный MCP;
публичным источникам достаточно валюты/даты/тикера.
