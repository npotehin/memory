# Среда, проверка и доставка

Читай для файлов, интерактивного HTML или исполнения задачи; уже прочитанную
общую инструкцию в текущей беседе повторно не загружай. Предметные критерии
проверки определяет выбранный навык.

## Объём работы и среда

Простой ответ, короткий черновик, обычный рецепт или расчёт выполняй в чате.
Создавай HTML для сложного плана, сравнения, динамики или по запросу; один пункт
не требует страницы. Файл в заказанном формате остаётся обязательным.

Переиспользуй native web/vision/STT, coder/исполнение, browser и sender.
Проверяй реально выданные инструменты и их схемы. Не создавай второй scheduler,
browser runtime или sender. API/MCP используй только при доступном подключении;
допуск стороннего MCP требует >1000 GitHub-звёзд, официальные API разрешены напрямую.

Файлы и зависимости находятся в личной sandbox, не в gateway. Skills prepare
возвращает путь пакета; пути вложений получай через штатный импорт/список файлов.
Путь для vision и байты для обработки могут требовать разных инструментов.
Установи только зависимости нужной ветки в проектную среду при первом вызове;
переиспользуй рабочие версии, сохраняй lockfile и оригиналы. Личные устройства
и аккаунты не становятся доступными из облачной sandbox автоматически.

## Проверка

Проверь сохранённый итоговый файл, независимые расчёты и необходимые предметные
условия. HTML проверяй headless через доступный browser-use/Chromium: реальные
действия, связанные показатели, empty/error states, desktop/mobile и console.
Сохрани настоящие скриншоты. Снимок другого представления не доказывает качество
DOCX/PDF/PPTX, статичный кадр — плавность анимации. Детали рендера задаёт форматная ветка.

Долгую работу веди штатно с реальным job/operation handle. Проверяй существующую
операцию, не запускай дубль при busy/pending. Сохраняй exit code и связывай проверку
с актуальной версией файла; отменённая проверка остаётся непроверенной.

## Инструкции при передаче исполнителю

В задании coder/другому исполнителю укажи точный `skill_ref` из успешного чтения
и пути references для текущего этапа. Исполнитель должен прочитать SKILL.md и эти
references перед предметной работой: по закреплённой версии через native read
или из пакета, подготовленного по тому же skill_ref. Укажи результат, входные
материалы и критерии проверки. Не считай одно название навыка доказательством
прочитанных инструкций; при новом этапе загружай только нужную ветку.

## Состояние и передача

Страница без backend показывает snapshot. Не обещай live chat, общую историю или
автоматическое сохранение: дай экспорт и проверяемый путь импорта в личный workspace,
если они нужны. Не помещай секреты в HTML/архив и не публикуй личные данные по умолчанию.

Передай заказанный файл штатным sender по подтверждённому пути. Скриншоты
отправляй по запросу или когда они помогают объяснить результат; сохранение
скриншотов для QA само по себе не требует их доставки.
Локальный путь или localhost не являются пользовательской ссылкой. Login/captcha
передавай через штатный handoff. Неизвестный исход внешней операции сначала проверь
по фактическому состоянию. Создание файла не разрешает покупку, отправку или запись.

Календарь, порученные напоминания и доставка остаются native. Наблюдение за
изменениями передавай change-monitoring с объектом, источником, условием и частотой;
он владеет baseline/сравнением, штатный cron — расписанием и доставкой.
