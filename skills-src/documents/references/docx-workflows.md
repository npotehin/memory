# DOCX: технические решения

## Обычные операции

python-docx позволяет создавать paragraphs, styles, таблицы, изображения, sections и headers/footers. Для новых документов задай Normal и Heading styles и размеры/поля страницы до наполнения. Размеры указывай через библиотечные единицы, например `Cm`/`Pt`, а не случайные EMU.

Для точечной правки сохраняй runs с разными стилями; совпадение текста может пересекать несколько runs. Сначала выясни структуру и выбери поддерживающий её метод. Hyperlinks, content controls, footnotes, tracked changes и некоторые embedded objects требуют отдельной проверки возможностей выбранного инструмента.

Не присваивай paragraph.text вслепую для локальной замены: это уничтожает runs
и встроенные элементы. Для сложной сохранности предпочитай доступную Office
автоматизацию. Кириллица требует совместимого шрифта; заголовок должен оставаться
с последующим текстом. Не имитируй таблицы пробелами и page breaks пустыми абзацами.

## Списки, таблицы и страницы

Используй существующие numbering definitions для правки шаблона. Для нового документа применяй соответствующие paragraph styles/numbering; отступы и табуляция должны быть согласованы. Таблицы не должны выходить за полезную ширину страницы; повтор заголовков проверяй в рендере. Для крупных таблиц горизонтальная секция или приложение лучше сверхмелкого шрифта.

Колонтитулы и page numbers зависят от sections и link-to-previous. Проверяй первую страницу, переходы sections и последнюю страницу. Не обещай конкретное число страниц до рендера: шрифты и layout engine меняют пагинацию.

## Render и PDF

LibreOffice/Word работают с копией и отдельным output directory. Для headless LibreOffice используй изолированный profile, чтобы не конфликтовать с другим процессом. Пересоздай preview после последней правки. PDF/скриншоты подтверждают внешний вид; повторное чтение DOCX подтверждает содержание. Нужны оба вида проверки, если задача включает верстку.

Официальная документация: https://python-docx.readthedocs.io/en/latest/user/quickstart.html
