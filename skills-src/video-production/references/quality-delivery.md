# Headless-проверка и доставка

## Проверка перед полным рендером

Отрендери характерные кадры: начало, читаемые состояния каждой сцены, середину сложного эффекта и обе стороны перехода. Просмотри их, затем сделай короткий тестовый экспорт сложного участка. Контактный лист показывает однообразие композиций, но не подтверждает движение.

Сохрани manifest проверки: scene ID → frame/time → ожидаемый текст/состояние → файл. Выбирай кадр после появления подписи, а вход/выход проверяй отдельно. Сортируй номера численно; подпиши ячейки контакта прямо из manifest. Не сообщай reviewer расположение по памяти: лексикографический порядок `1,10,11,2` и неверная сетка создают ложные «пропавшие сцены».

Дай browser/reviewer конкретные критерии: чтение на мобильном размере, crop/лица, пустые поля, контраст, разнообразие сцен, устойчивость заголовков. Просмотр короткого клипа или последовательности кадров должен отдельно подтвердить движение и смену текста. Исправляй доказанные дефекты; плановое разнообразие композиций само по себе не ошибка.

Проверь обратный seek и повтор одного времени: изображение не должно зависеть от истории воспроизведения. Шрифты, локальные изображения, видео и звук должны быть доступны без обязательной сети во время capture. Если validator сообщает ноль samples из-за lint error, это отсутствие проверки, не успех.

Время и параллелизм рендера измеряй на пробном участке. Уменьшай параллелизм при нехватке ресурсов; сложность эффекта и размер кадров согласуй с целью. Не устанавливай второй браузер или сервис, когда существующий достаточен. Preview для ревью — опция, не требование GUI в среде без экрана.

Бенчмарк — короткое видео в целевых dimensions/FPS на представительном сложном участке, с фактическими числом кадров и elapsed time. Скорость still или простого ffmpeg-теста не предсказывает скорость многослойного ролика. Отделяй cold start от покадровой работы; сообщай диапазон оценки и уточняй его по реальному прогрессу. Статичные blur/texture заранее подготовь как ассеты; не считай тяжёлые полноэкранные эффекты на каждом кадре без нужды.

Если browser-ревью зависло или отменено, сохрани статус «не проверено» и проведи осмотр доступным viewer либо более коротким точечным вызовом. Успех команды генерации stills не равен успеху их осмотра. После исправлений проверяй новую версию, а не прежний контактный лист.

## Команды и фоновые шаги

Сохраняй настоящий exit code рендера: удобнее записать stdout/stderr в лог, а tail читать отдельной диагностической командой. Pipeline через `tail` без `pipefail` может вернуть успех после падения renderer; последующий успешный `echo` тоже маскирует ошибку. Проверка ffprobe дополняет статус команды, но старый файл в том же пути не подтверждает новый render. Используй отдельный путь для итерации и сверяй свежий результат.

Для tracked operations следуй штатному контракту. Вызовы help/version и чтение прогресса — diagnostic; подготовка ассетов, рендер и необходимая проверка — required. Не объединяй подготовку с необязательной CLI-диагностикой, которая может ложно уронить весь шаг. `step_key` обозначает одно действие с теми же аргументами: новая творческая итерация получает новый ключ. Repair/generation применяй только к подтверждённо неуспешному шагу по правилам инструмента, не для повторного запуска успешного шага с другим кодом.

На запрос статуса инспектируй существующую operation; не запускай второй renderer и не меняй её принадлежность задаче ради просмотра. Pending, reconciling и зависший reviewer не означают готовый файл. Если проверка требует замены, сохрани явную связь с новой успешной проверкой; не оставляй отменённый required-step единственным результатом приёмки.

## Экспортированный файл

Используй доступные ffmpeg/ffprobe или проверенный ffmpeg workflow. Минимальные команды для локального файла:

```sh
ffprobe -v error -show_format -show_streams -of json final.mp4
ffmpeg -v error -i final.mp4 -f null -
```

Сверь фактическую длительность с планом, video dimensions/FPS, pixel format, кодеки и ожидаемые audio streams. MP4/H.264/AAC обычно подходят массовой доставке, но конкретный формат выбирается по запросу; silent video не требует AAC. Допуск длительности учитывает шаг кадра и audio padding, а не произвольное большое расхождение.

Из **готового MP4** извлеки начало, финал и характерные кадры; осмотри все сцены и переходы. Неожиданный чёрный/замёрзший участок ищи отдельно: детектор сообщает кандидатов, но тёмный кадр или намеренный hold могут быть содержанием. Проверь отсутствие обрезанных слов, растянутого изображения, провала на монтажном стыке и обрыва звука. Для анимации просматривай короткую последовательность, не только один кадр.

Если есть звук, измерь peak/громкость и проверь длительность дорожек; при возможности прослушай. Не выдавай audio statistics за проверку качества речи. Для captions сопоставь несколько реплик с аудио и финальными кадрами, включая последнюю реплику.

После правки обновляй файл, к которому относятся проверки. Ошибка декодирования или пропавший обязательный ассет блокируют статус «готово». Если проверен один движок/формат, не переноси вывод на второй.

## Передача и воспроизведение

Передай реальный файл штатным sender и небольшой постер. По запросу архив проекта содержит source, выбранные локальные ассеты, media manifest, lockfile, input props, субтитры и точную команду рендера. Исключи node_modules, caches, transient frames, auth logs, токены и профиль браузера.

Локальный HTTP preview подходит агентной проверке; пользователь получает его только если URL действительно доступен ему. Не подменяй MP4 ссылкой на localhost, логом «render started» или записью браузера. Сохрани отчёт того, что реально проверено и какие ограничения остались; самооценка «10/10» не является доказательством.
