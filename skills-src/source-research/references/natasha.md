# Natasha: русский поиск и проверяемые кандидаты фактов

## Подготовка при первом вызове

В sandbox проекта создай или переиспользуй отдельную venv для documents. Установи
закреплённый стек из [natasha-requirements.txt](natasha-requirements.txt):

```sh
python -m venv .documents-venv
.documents-venv/bin/python -m pip install -r /path/from/skills-prepare/references/natasha-requirements.txt
```

Используй путь, который вернул skills prepare, а не gateway filesystem.
Модели morphology/NER и Navec входят в Natasha wheel; ключи, сервис и локальная
генеративная модель не нужны. Это локальный нейросетевой NLP на CPU, не LLM.
После установки сделай smoke на реальном источнике и проверь CLI search/facts.
Не устанавливай NLP в gateway или глобальный Python. Natasha 1.6.0 MIT;
зависимости сохраняют свои upstream-лицензии. Upstream:
[Natasha](https://github.com/natasha/natasha),
[pymorphy3](https://github.com/no-plagiarism/pymorphy3).

Штатный MorphVocab использует старый pymorphy2. Bundled adapter переиспользует
Natasha MorphForm/lemma selection с pymorphy3 вместо глобальных compatibility
patches. Обновляй закрепления только после проверки на целевой версии Python.

## Поиск

```sh
.documents-venv/bin/python /prepared/scripts/grounded.py --corpus ./corpus --normalizer natasha search --question 'ребёнок'
```

`auto` предпочитает Natasha, если пакет установлен; без Natasha использует bundled
Snowball. Неполная/сломанная установка выдаёт ошибку, не молча меняет алгоритм.
`--normalizer snowball` — явный режим без моделей. Каждый Corpus владеет своим
адаптером. Один проект запускай с одним закреплённым стеком: чередование режимов
приводит к повторным перестроениям индекса.

Natasha добавляет контекстные леммы (дети → ребёнок, людям → человек) к исходному
Snowball-каналу. Нормализация выполняется по небольшим блокам, оригиналы/цитаты
остаются неизменны. Установленная версия стека входит в search_version; индекс
перестраивается транзакционно из сохранённых chunks. Семантический поиск,
синонимы и расширение через Navec similarity пока не реализованы. Короткий запрос
может дать иную морфологию, чем предложение; lexical channel сохраняет запасной
путь. Сходные леммы не доказывают совпадение людей или организаций.

## Факты с точной привязкой

```sh
.documents-venv/bin/python /prepared/scripts/grounded.py --corpus ./corpus --normalizer natasha facts --source-id SOURCE_ID --entities --output ./facts.jsonl
```

Потоково обрабатывает все извлечённые chunks выбранных версий. Date/Money grammar
выдаёт кандидаты дат и сумм; `--entities` дополнительно загружает NER для людей,
организаций и мест, затем нормализует PER/LOC и разбирает ФИО внутри PER.
ORG остаётся исходным: корректная нормализация сложных организаций может требовать
syntax parser, который здесь не включён. Каждый JSONL record содержит source_id,
chunk_id, locator, quote, смещения внутри оригинального chunk и status=candidate.
Результат не помещает весь корпус в память; JSONL нельзя читать целиком ради
обзора большого корпуса. Границы chunks могут разрезать сущность; отсутствие
кандидата не доказывает отсутствие реквизита. Coverage относится к извлечённому
тексту, OCR/пустые страницы остаются в gaps.

Это вспомогательные evidence для:

- протокола: кандидаты участников и явно названных дат, без приписывания задач;
- заявления/письма: сверка написания ФИО, организаций, дат и сумм с источником;
- сравнения версий: таблица изменившихся кандидатов рядом с полным section diff;
- notebook: фильтры/указатель людей и мест, ссылки на исходные фрагменты;
- проверки перед отправкой: подозрительные расхождения в реквизитах.

**Проверяй цитаты до использования значений.** На smoke предложение «выплатят
15 000 рублей 12 октября 2026 года» дало money.amount=15000.12: грамматика
захватила начало соседней даты. NER тоже ошибается, особенно вне новостного домена.
Нельзя автоматически заполнять юридически значимые поля, склеивать личности,
объявлять противоречие, дедлайн или обязательство по одному NLP-кандидату.
Это не OCR, исправление STT, модель задач/решений или проверка смысла договора.
Адресные грамматики, syntax parsing, автоматическая маскировка персональных
данных и synonym expansion пока кандидаты, не реализованные возможности.
